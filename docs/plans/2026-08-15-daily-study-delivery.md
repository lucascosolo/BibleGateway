# Daily Study and Discovery Delivery Plan

> **For agentic workers:** if this plan has more than ~4 tasks, use the `scoped-delivery` skill to implement it in 1-3 task chunks via fresh subagents. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the approved ongoing daily-study experience, its curated catalog, research layers, reading plans, calendar and device reminders, and complete rendered verification.

**Architecture:** Delivery is split into six independently reviewable plans. Corpus/editorial foundations land first, then the 60-day catalog, the core study experience, research layers and plans, reminders, and final acceptance. Each plan produces working, tested software and names the exact interfaces the next plan consumes.

**Tech Stack:** Next.js 15 App Router, React 19, TypeScript strict, SQLite/better-sqlite3, Vitest + Testing Library, Tailwind v4/CSS tokens, Web Push, service workers, Playwright on the VPS.

## Global Constraints

- Read `ARCHITECTURE.md` and `docs/superpowers/specs/2026-08-15-daily-study-discovery-design.md` before editing.
- `verse_id` (`BBCCCVVV`) is the only passage address; every range expansion uses real ids from `getExistingVerseIds`.
- All scripture, including study sessions and plan steps, renders through `components/passage/PassageRenderer.tsx`; extend lint guards for every new bypass route.
- `bible.db` remains immutable and rebuildable; `userdata.db` remains writable and survives corpus rebuilds.
- All curated claims are first-party reviewed and citation-backed; no generated commentary or community submissions.
- User-facing specialized biblical terms come from `lib/lexicon.ts`; primary study labels remain plain English.
- No raw hex colors in components; use existing light/dark tokens and verify contrast on every surface.
- Mobile-first; `density` remains semantic and physical fit remains container-query driven.
- No `node_modules` on the laptop. Ingests, installs, builds, full tests, Playwright, servers, and screenshots run on the VPS.
- Run `scripts/teardown.sh` and audit the VPS after every test cycle.
- Production push activation is a separate human checkpoint; implementation stops at verified dry-run wiring.

## Repository preflight

The repository began with all application source untracked and the approved design as its root
commit. Before creating a worktree or dispatching implementation, create one explicit baseline
commit containing the current non-generated source. This is not a feature change; it gives later
chunks a real diff and makes worktrees contain the project.

```bash
git status --short --branch
git check-ignore data/bible.db data/userdata.db apps/web/node_modules packages/ingest/node_modules
git add .gitignore AGENTS.md ARCHITECTURE.md apps packages scripts docs/ORIGINAL-LANGUAGES.md docs/REVIEW-BRIEF.md docs/WORK-IN-PROGRESS.md docs/reviews
git diff --cached --check
git commit -m "chore: establish Jot source baseline"
```

Do not add `data/bible.db`, `data/userdata.db`, `node_modules`, `.next`, screenshots generated by a
new run, `.aipool-artifacts`, or any secret. Confirm the working tree is clean before using the
`using-git-worktrees` skill.

## End-to-end completion command

The final plan must leave fresh evidence for all three separate claims:

```bash
./scripts/sync-and-ingest.sh
./scripts/sync-and-build.sh
# From /srv/scratch/shotrig on the VPS:
node shoot.mjs /srv/scratch/jot/study-shots http://127.0.0.1:3987
node measure.mjs http://127.0.0.1:3987
./scripts/teardown.sh
```

Expected: ingest validation succeeds with at least 60 consecutive scheduled discoveries; build,
lint, unit tests, font gate, smoke gate, and rendered accessibility gate exit 0; screenshot count
matches the expanded route/state matrix; measurement reports no overflow or typeface failures;
teardown confirms no Jot preview, reminder worker, tunnel, or temporary timer remains running.
