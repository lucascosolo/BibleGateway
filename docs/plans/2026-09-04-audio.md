# Audio: audiobook playback + spoken Hebrew/Greek words

Living plan and handoff. Started 2026-09-04. Everything under "Verified" was run and read in a
session; everything under "Decided" is a design choice with its reason; "Open" is unresolved.

## What Lucas asked for (verbatim intent, 2026-09-04)

1. **An audio control panel in the reader.** Press play and it starts reading at the selected
   verse, or at the top of the page when nothing is selected. Plays like an audiobook and moves
   to the next page automatically. Pre-made recordings per translation, not runtime TTS.
2. **A small speaker button under each Hebrew/Greek word or phrase** (Google Translate style) in
   the interlinear, playing the original-language word.
3. **Only sources whose licences allow unrestricted use in a free product.** "Any whose licenses
   allow unrestricted use in a free product, let's go ahead and implement them." Non-commercial
   (NC) and no-derivatives (ND) sources are out unless Lucas explicitly changes that.
4. Asked whether any human-read, period-accurate Hebrew/Greek recording exists so TTS can be
   avoided. Answer below.
5. Side question: the `/lashon/H853` page says "Rendered in the King James Version as:
   [as such unrepresented in English]" — why? (Answer: H853 is *ʾēt*, the untranslated
   direct-object marker; the bracketed text is Strong's own note that the word has no English
   equivalent, and the page prints the raw usage field under a label that assumes it lists
   renderings. Fix: detect the bracketed note and word it plainly. Not yet fixed.)
6. Side question: is there a freely licensed "simplified KJV" that keeps its character? NKJV is
   copyrighted (Thomas Nelson). Candidates that are public domain: **American King James
   Version** (1999, ~55,000 archaic words modernised, explicitly public domain) and **Webster's
   1833 revision** (KJV with only the hardest expressions modernised, public domain). Not yet
   ingested; a decision for Lucas.

## Decided

- **Per-word Hebrew audio is cut from Be'eri, not synthesised.** The forced aligner emits
  word-level timestamps; a word's clip is a `[start,end]` slice of the chapter file. Pronounced
  in context by a human. No Greek per-word button until a licensed source exists.
- **Separate artifact: `data/audio.db` + `data/audio/<edition>/<bb>-<ccc>.m4a`.** Not merged into
  `bible.db` (the corpus rebuild must not depend on a 260-hour alignment run) and not in the
  repo. The app feature-detects: no `audio.db`, no player.
- **Alignment tool: torchaudio `MMS_FA`** (wav2vec2 forced aligner, 1,100+ languages, `<star>`
  wildcard token for windowed alignment over long files). Runs on this PC (16 threads, GTX 980 Ti
  = sm_52, so torch 2.4.1+cu118, not a CUDA 12.8+ build). Not aeneas (needs espeak, no sudo here)
  and not Whisper (transcribes; we already have the text).
- **Verse timings keyed by canonical `verse_id`**, so the player, the highlight and the
  interlinear all use the one address (AGENTS.md invariant 1). Hebrew fragments are assembled
  per canonical verse from `original_words` (which already carries the WLC→canonical mapping).
- **Player lives in the app shell, not the page**, driven by a store: the page publishes the
  current chapter's audio data on mount; the player keeps the `<audio>` element alive across
  client navigations so chapter N ending → `router.push(next)` → chapter N+1 plays without a new
  user gesture. Media Session API for lock-screen controls.
- **Start position:** a DOM selection inside a verse wins; otherwise the first verse rendered.
- **Translations with no recording (YLT, DBY, JPS, Brenton):** the control shows "no audio for
  this translation" and offers the three that have it. No silent fallback to a different text.
- Encode chapters to mono AAC ~48 kbps in `.m4a` (universal playback, ~20 MB/hour).
